03 · ROUTE DISCOVERY

Traceroute comparison

Five traceroute attempts were performed for each destination. Traceroute reveals responding intermediate routers; some routers may not reply to probes.

Kean University · www.kean.edu

Destination resolved to 131.125.16.38 (web.kean.edu). The initial trace showed the local gateway and Comcast network hops, then a GTT router at New York City; subsequent hops did not respond.

Run 1Responding through hop 11 · GTT router last seen · later hops timed out

Run 3Responding through hop 11 · GTT router · later hops timed out
Run 4Responding through hop 11 · GTT router · later hops timed out
Run 5Responding through hop 11 · GTT router · later hops timed out

The destination did not respond in the collected traces. Timeout markers (*) indicate no reply to the traceroute probe, not necessarily a broken route.

Google · www.google.com

The tested address was 142.251.157.119. Each of the five runs reached the destination in the recorded output.

Run 18 hops to destination
Run 27 hops to destination
Run 39 hops to destination
Run 48 hops to destination
Run 58 hops to destination

The routes varied slightly between runs. Google was reachable and returned a response at the destination hop.

Observations

  • The first hop was the local gateway, 10.0.0.1.
  • Intermediate hops included Comcast network routers and, in the Kean trace, a GTT router.
  • Some hop responses were missing, likely because those routers did not respond to traceroute probes.
  • Google traces reached the destination in approximately 7–9 hops; Kean traces stopped receiving responses after intermediate hops.

Latency values and hop sequences varied among the runs. The longest hop count is not the same as the longest latency.

04 · ADDRESS RESOLUTION

ARP cache experiment

Examined the local ARP cache, deleted the gateway mapping, pinged the gateway, and checked the table again.

Experiment outcome

  1. Displayed cache using arp -a.
  2. Deleted gateway entry with sudo arp -d 10.0.0.1.
  3. Confirmed deletion command reported the entry deleted.
  4. Pinged gateway with ping -c 1 10.0.0.1.
  5. Viewed ARP table again; gateway mapping was visible.

Ping immediately after deletion

73.532 ms single reply · 0% loss

The gateway mapping was present again after the ping. This demonstrates the local ARP resolution process: the host needs the destination's link-layer address to send packets on the local network.

05 · RESULTS & CONCLUSION

What the experiments demonstrated

The lab provided practical experience inspecting a computer's network settings, reading routing information, testing connectivity, tracing routes to remote destinations, and examining ARP address mappings. The temporary IPv4 configuration was applied and successfully restored through DHCP. Ping tests received replies without packet loss in the tested samples. Traceroute showed the local gateway and upstream routing devices, while response timeouts illustrated that some intermediate routers do not reply to probes. The ARP cache experiment showed that the gateway mapping was visible again after network communication.

A successful network connection depends on correctly configured addressing, gateway and DNS settings, and local link-layer address resolution—while diagnostic tools provide only a partial view of the network path.
